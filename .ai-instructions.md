## 🔴🟢🔄 Metodología Core: Desarrollo Guiado por Pruebas (TDD)

### Ley de TDD en este Curso
Para todo código Python desarrollado por estudiantes (y el asistente), rige la siguiente regla:
```
NINGÚN CÓDIGO DE PRODUCCIÓN SIN UNA PRUEBA UNITARIA FALLIDA PRIMERO
```

### Ciclo RED-GREEN-REFACTOR en Programación Básica

1. **RED (Escribir Prueba Fallida)**:
   ```python
   def test_es_par():
       # Debe fallar porque la función no existe aún
       assert es_par(4) is True
       assert es_par(5) is False
   ```
2. **GREEN (Mínima Implementación)**:
   ```python
   def es_par(n: int) -> bool:
       return n % 2 == 0
   ```
3. **REFACTOR (Optimizar y Pulir)**:
   Asegurar tipos, mejorar legibilidad o rendimiento sin romper la prueba.

## 📋 Estructura Pedagógica de las Unidades (.md)

Cada unidad o lección en Markdown debe seguir un formato estricto que el pipeline de agentes de IA enriquecerá y convertirá en celdas de notebook:

1. **Título de la Lección** (`# Título` y objetivos en `📚 OBJETIVOS DE APRENDIZAJE`).
2. **Explicación Teórica** (conceptos lógicos, matemáticos y diagramas de flujo con Mermaid).
3. **Ejemplo Práctico** demarcado obligatoriamente por `### 💻 Ejemplo: [Nombre]`.
4. **Bloque de Código** en Python (` ```python `) o Pseudocódigo (` ```pseudocodigo `).
5. **Pruebas Unitarias** con `pytest` para automatizar la verificación del código del ejemplo.
6. **Síntesis y Ejercicios** para autoevaluación al final del módulo.

## 🛠️ Estilo de Código y Estándares

- **Tipado Estricto**: Todas las funciones deben incluir anotaciones de tipo (Type Hints).
- **Docstrings Completos**: Usar docstrings en estilo Google documentando argumentos, retornos y excepciones.
- **Evitar Números Mágicos**: Definir constantes al inicio de las celdas con nombres en mayúscula.
- **Validación de Entradas**: Comprobar condiciones de borde (inputs inválidos, negativos, tipos incorrectos) y levantar excepciones claras.
